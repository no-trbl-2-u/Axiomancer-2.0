## TypeScript Standards

### Type Definitions

**DO**:
```typescript
// ✅ Explicit types on function parameters and returns
function calculateDamage(
  attack: number, 
  defense: number
): number {
  return Math.max(1, attack - defense);
}

// ✅ Interface for object shapes
interface Character {
  id: string;
  name: string;
  level: number;
}

// ✅ Type aliases for unions and primitives
type GamePhase = 'exploration' | 'combat' | 'dialogue' | 'event';

// ✅ Explicit property types
const character: Character = {
  id: '123',
  name: 'Hero',
  level: 1
};
```

**DON'T**:
```typescript
// ❌ Using 'any' type
function doSomething(data: any) { /* ... */ }

// ❌ Implicit any
function doSomething(data) { /* ... */ }

// ❌ Omitting return types
function calculateDamage(attack: number, defense: number) {
  return attack - defense;  // What type is returned?
}

// ❌ Leaving unused types in the codebase
interface UnusedType {  // Remove if not used!
  foo: string;
}
```

### Interface vs Type

**Use `interface` for**:
- Object shapes that might be extended
- Public APIs
- Class definitions

```typescript
interface Character {
  id: string;
  name: string;
}

// Can be extended later
interface Hero extends Character {
  heroicLevel: number;
}
```

**Use `type` for**:
- Unions
- Intersections
- Primitives
- Function signatures
- Complex computed types

```typescript
type GamePhase = 'exploration' | 'combat' | 'dialogue';
type AttackType = 'physical' | 'mind' | 'ailment';
type Nullable<T> = T | null;
```

### Strict TypeScript Settings

**tsconfig.json** should have:
```json
{
  "compilerOptions": {
    "strict": true,
    "noImplicitAny": true,
    "strictNullChecks": true,
    "strictFunctionTypes": true,
    "strictBindCallApply": true,
    "strictPropertyInitialization": true,
    "noImplicitThis": true,
    "alwaysStrict": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "noImplicitReturns": true,
    "noFallthroughCasesInSwitch": true
  }
}
```

### Handling Null and Undefined

**DO**:
```typescript
// ✅ Optional chaining
const userName = user?.profile?.name;

// ✅ Nullish coalescing
const displayName = user?.name ?? 'Anonymous';

// ✅ Type guards
if (user !== null && user !== undefined) {
  console.log(user.name);
}

// ✅ Optional properties
interface Config {
  apiUrl: string;
  timeout?: number;  // Optional
}
```

**DON'T**:
```typescript
// ❌ Non-null assertion without good reason
const name = user!.name;  // Dangerous if user could be null

// ❌ Using || for default values (wrong behavior with 0, '', false)
const timeout = config.timeout || 5000;  // Use ?? instead
```

### Generic Types

**DO**:
```typescript
// ✅ Generic function
function getById<T extends { id: string }>(
  items: T[], 
  id: string
): T | undefined {
  return items.find(item => item.id === id);
}

// ✅ Generic interface
interface ApiResponse<T> {
  data: T;
  error: string | null;
}
```

### Type Exports

**DO**:
```typescript
// ✅ Named exports
export interface Character { /* ... */ }
export type GamePhase = 'exploration' | 'combat';

// ✅ Grouped exports
export type {
  Character,
  Enemy,
  GameState
};
```

**DON'T**:
```typescript
// ❌ Default exports for types (use named exports)
export default interface Character { /* ... */ }
```

## React Standards

### Component Structure

**Functional Components with TypeScript**:
```typescript
import React from 'react';
import styled from '@emotion/styled';

interface Props {
  title: string;
  isActive?: boolean;
  onAction: (id: string) => void;
}

export const MyComponent: React.FC<Props> = ({ 
  title, 
  isActive = false, 
  onAction 
}) => {
  // 1. State hooks
  const [count, setCount] = React.useState<number>(0);
  
  // 2. Store subscriptions
  const gameState = useGameStore(state => state.gameState);
  
  // 3. Effects
  React.useEffect(() => {
    console.log('Component mounted');
    return () => {
      console.log('Component unmounted');
    };
  }, []);
  
  // 4. Event handlers
  const handleClick = React.useCallback(() => {
    onAction(title);
  }, [onAction, title]);
  
  // 5. Early returns
  if (!isActive) {
    return null;
  }
  
  // 6. Main render
  return (
    <Container>
      <Title>{title}</Title>
      <Button onClick={handleClick}>
        Count: {count}
      </Button>
    </Container>
  );
};

// 7. Styled components at bottom
const Container = styled.div`
  padding: 20px;
`;

const Title = styled.h2`
  font-size: 24px;
`;

const Button = styled.button`
  padding: 10px 20px;
`;
```

### Component Best Practices

**DO**:
```typescript
// ✅ Use React.memo for expensive components
export const ExpensiveComponent = React.memo<Props>(({ data }) => {
  // Expensive rendering logic
});

// ✅ Use useCallback for functions passed as props
const handleClick = React.useCallback(() => {
  doSomething();
}, [dependency]);

// ✅ Use useMemo for expensive calculations
const expensiveValue = React.useMemo(() => {
  return calculateExpensiveValue(data);
}, [data]);

// ✅ Destructure props early
export const MyComponent: React.FC<Props> = ({ title, count }) => {
  // Use title and count directly
};
```

**DON'T**:
```typescript
// ❌ Create functions inside render without useCallback
const handleClick = () => {  // Re-created every render!
  doSomething();
};

// ❌ Use index as key in lists
{items.map((item, index) => (
  <Item key={index} {...item} />  // Bad!
))}

// ❌ Mutate state directly
setCharacter(character.level = 5);  // Wrong!

// ✅ Create new object
setCharacter({ ...character, level: 5 });
```

### Hooks Rules

**DO**:
- ✅ Call hooks at the top level (not in conditions/loops)
- ✅ Call hooks only in React functions
- ✅ Use descriptive names for custom hooks (start with "use")
- ✅ Document dependencies in useEffect/useCallback/useMemo

**DON'T**:
- ❌ Call hooks conditionally
- ❌ Call hooks in regular JavaScript functions
- ❌ Forget to list dependencies
- ❌ Use stale closures

```typescript
// ❌ Wrong - conditional hook
if (condition) {
  useEffect(() => { /* ... */ }, []);
}

// ✅ Correct - condition inside hook
useEffect(() => {
  if (condition) {
    // Do something
  }
}, [condition]);
```

### Event Handlers

**Naming Convention**:
```typescript
// ✅ Use "handle" prefix for handlers
const handleClick = () => { /* ... */ };
const handleSubmit = () => { /* ... */ };
const handleChange = (e: React.ChangeEvent<HTMLInputElement>) => { /* ... */ };

// ✅ Use "on" prefix for props
interface Props {
  onClick: () => void;
  onSubmit: (data: FormData) => void;
}
```

**Type-Safe Event Handlers**:
```typescript
// ✅ Properly typed events
const handleChange = (e: React.ChangeEvent<HTMLInputElement>): void => {
  const value = e.target.value;
};

const handleKeyDown = (e: React.KeyboardEvent<HTMLDivElement>): void => {
  if (e.key === 'Enter') {
    // Handle enter
  }
};
```

## Zustand Store Standards

### Store Structure

```typescript
import { create } from 'zustand';
import { devtools, persist } from 'zustand/middleware';

interface MyState {
  // State properties
  count: number;
  user: User | null;
  
  // Actions
  increment: () => void;
  setUser: (user: User) => void;
  reset: () => void;
}

export const useMyStore = create<MyState>()(
  devtools(
    persist(
      (set, get) => ({
        // Initial state
        count: 0,
        user: null,
        
        // Actions
        increment: () => set(state => ({ count: state.count + 1 })),
        
        setUser: (user: User) => set({ user }),
        
        reset: () => set({ count: 0, user: null }),
      }),
      {
        name: 'my-store',  // localStorage key
        partialize: (state) => ({
          // Only persist these fields
          user: state.user,
        }),
      }
    ),
    {
      name: 'my-store-devtools',  // DevTools name
    }
  )
);
```

### Store Best Practices

**DO**:
```typescript
// ✅ Use functional updates for state that depends on previous state
set(state => ({ count: state.count + 1 }))

// ✅ Group related actions
const updateCharacter = (updates: Partial<Character>) => {
  set(state => ({
    gameState: {
      ...state.gameState,
      character: { ...state.gameState.character, ...updates }
    }
  }));
};

// ✅ Use get() to access current state inside actions
const saveAndLog = () => {
  const state = get();
  console.log('Saving state:', state);
  saveToBackend(state);
};
```

**DON'T**:
```typescript
// ❌ Mutate state directly
set(state => {
  state.count++;  // Wrong!
  return state;
});

// ❌ Create new function references in selectors
const handleClick = useStore(state => () => state.increment());  // Bad!

// ✅ Extract the function
const increment = useStore(state => state.increment);
const handleClick = () => increment();
```

## Styling Standards

### Emotion Styled Components

**DO**:
```typescript
import styled from '@emotion/styled';

// ✅ Use semantic names
const Container = styled.div`
  display: flex;
  flex-direction: column;
`;

// ✅ Use template literals for conditional styles
const Button = styled.button<{ isActive: boolean }>`
  background: ${props => props.isActive ? '#4a90e2' : '#ccc'};
  color: white;
  padding: 10px 20px;
  
  &:hover {
    opacity: 0.8;
  }
  
  &:disabled {
    opacity: 0.5;
    cursor: not-allowed;
  }
`;

// ✅ Compose styles
const PrimaryButton = styled(Button)`
  background: #4a90e2;
  font-weight: bold;
`;

// ✅ Use theme if available
const ThemedButton = styled.button`
  background: ${props => props.theme.colors.primary};
`;
```

**DON'T**:
```typescript
// ❌ Inline styles (use styled-components instead)
<div style={{ padding: '20px', background: 'blue' }}>
  
// ❌ Non-semantic names
const Div1 = styled.div``;
const BlueBox = styled.div``;  // What if color changes?

// ❌ Magic numbers without explanation
const Box = styled.div`
  width: 347px;  // Why 347?
`;

// ✅ Use variables
const BOX_WIDTH = 347;  // Or better: get from theme
const Box = styled.div`
  width: ${BOX_WIDTH}px;
`;
```

### CSS Best Practices

**DO**:
- ✅ Use flexbox or grid for layouts
- ✅ Use relative units (rem, em, %) when appropriate
- ✅ Mobile-first responsive design
- ✅ Use CSS variables via theme
- ✅ Add comments for complex layouts

**DON'T**:
- ❌ Use `!important` (refactor specificity instead)
- ❌ Use absolute positioning unless necessary
- ❌ Hardcode colors (use theme)
- ❌ Use magic numbers without explanation

## Error Handling

### Frontend Error Handling

**DO**:
```typescript
// ✅ Try-catch for async operations
const saveCharacter = async () => {
  try {
    await characterService.saveCharacter(data);
    showSuccessMessage('Character saved!');
  } catch (error) {
    console.error('Failed to save character:', error);
    showErrorMessage('Failed to save character. Please try again.');
  }
};

// ✅ Type-safe error handling
const handleError = (error: unknown) => {
  if (error instanceof Error) {
    console.error(error.message);
  } else if (typeof error === 'string') {
    console.error(error);
  } else {
    console.error('Unknown error:', error);
  }
};

// ✅ Error boundaries for component errors
class ErrorBoundary extends React.Component<Props, State> {
  static getDerivedStateFromError(error: Error) {
    return { hasError: true };
  }
  
  componentDidCatch(error: Error, errorInfo: React.ErrorInfo) {
    console.error('Component error:', error, errorInfo);
  }
  
  render() {
    if (this.state.hasError) {
      return <ErrorFallback />;
    }
    return this.props.children;
  }
}
```

**DON'T**:
```typescript
// ❌ Silent failures
try {
  await doSomething();
} catch (error) {
  // Empty catch - user has no idea what happened
}

// ❌ Catching errors just to re-throw
try {
  await doSomething();
} catch (error) {
  throw error;  // Pointless
}

// ❌ Generic error messages
catch (error) {
  alert('Error');  // What error?
}
```

### Backend Error Handling

**DO**:
```typescript
// ✅ Throw typed errors
class NotFoundError extends Error {
  statusCode = 404;
  constructor(message: string) {
    super(message);
    this.name = 'NotFoundError';
  }
}

// ✅ Consistent error responses
res.status(statusCode).json({
  error: message,
  // stack: process.env.NODE_ENV === 'development' ? error.stack : undefined
});

// ✅ Validate input
if (!email || !password) {
  return res.status(400).json({ error: 'Email and password required' });
}
```

## Comments and Documentation

### When to Comment

**DO Comment**:
- ✅ Complex algorithms or business logic
- ✅ Non-obvious code decisions
- ✅ Workarounds for bugs or limitations
- ✅ TODOs and FIXMEs
- ✅ Public API functions (JSDoc)

**DON'T Comment**:
- ❌ Obvious code
- ❌ What the code does (code should be self-documenting)
- ❌ Commented-out code (delete it)

### Good Comments

```typescript
// ✅ Explains WHY, not WHAT
// We debounce saves by 500ms to avoid hammering the backend
// during rapid user actions (e.g., stat point allocation)
setTimeout(() => saveGame(), 500);

// ✅ JSDoc for exported functions
/**
 * Calculates damage dealt based on attacker and defender stats
 * @param attackerStat - The attacker's relevant stat (physical/mind/ailment)
 * @param defenderStat - The defender's relevant defense stat
 * @returns The damage dealt (minimum 1)
 */
export function calculateDamage(
  attackerStat: number, 
  defenderStat: number
): number {
  return Math.max(1, attackerStat - defenderStat);
}

// ✅ TODOs
// TODO: Implement skill prerequisites check before allowing equip
// FIXME: Character ID generation using Date.now() could cause collisions

// ✅ Warnings about tricky code
// WARNING: This regex is fragile. If the input format changes, this will break.
const pattern = /^[A-Z]{3}-\d{4}$/;
```

### Bad Comments

```typescript
// ❌ Obvious
// Increment the counter
counter++;

// ❌ Outdated (worse than no comment)
// Set to 100  (but code says 200)
const maxHP = 200;

// ❌ Commented-out code
// const oldFunction = () => { /* ... */ };
// DELETE THIS INSTEAD

// ❌ Vague
// Do the thing
doSomething();
```

## Testing Standards

### Unit Test Structure

```typescript
describe('calculateDamage', () => {
  it('should calculate damage correctly', () => {
    const damage = calculateDamage(50, 30);
    expect(damage).toBe(20);
  });
  
  it('should return minimum 1 damage', () => {
    const damage = calculateDamage(10, 50);
    expect(damage).toBe(1);
  });
  
  it('should handle zero stats', () => {
    const damage = calculateDamage(0, 0);
    expect(damage).toBe(1);
  });
});
```

### Test Best Practices

**DO**:
- ✅ Test behavior, not implementation
- ✅ One assertion per test (generally)
- ✅ Use descriptive test names
- ✅ Test edge cases
- ✅ Test error conditions

**DON'T**:
- ❌ Test private implementation details
- ❌ Write brittle tests that break on refactoring
- ❌ Skip error case testing

## Git Commit Standards

### Commit Message Format

```
<type>(<scope>): <subject>

<body>

<footer>
```

**Types**:
- `feat`: New feature
- `fix`: Bug fix
- `docs`: Documentation only
- `style`: Formatting, missing semicolons, etc.
- `refactor`: Code change that neither fixes a bug nor adds a feature
- `perf`: Performance improvement
- `test`: Adding tests
- `chore`: Updating build tasks, package manager configs, etc.

**Examples**:
```
feat(combat): add buff/debuff system to combat engine

Implement BuffDebuff interface and apply effects during damage calculation.
Buffs and debuffs now properly modify stats and expire after duration.

Closes #42

---

fix(character): prevent negative HP from healing overflow

Added bounds check to ensure currentHP never exceeds maxHP.

---

refactor(gameStore): extract stat calculation to utility module

Moved stat calculation logic from gameStore to utils/statCalculations.ts
for better separation of concerns.

---

docs(readme): add Docker setup instructions
```

### Commit Best Practices

**DO**:
- ✅ Make atomic commits (one logical change per commit)
- ✅ Write clear, descriptive commit messages
- ✅ Reference issue numbers when applicable
- ✅ Commit often

**DON'T**:
- ❌ Commit broken code
- ❌ Commit commented-out code
- ❌ Use vague messages ("fix stuff", "WIP", "asdf")
- ❌ Commit node_modules or build artifacts (use .gitignore)

## Performance Best Practices

### React Performance

**DO**:
```typescript
// ✅ Memoize expensive components
const ExpensiveList = React.memo(({ items }) => {
  return items.map(item => <Item key={item.id} {...item} />);
});

// ✅ Use keys properly in lists
{items.map(item => (
  <Item key={item.id} {...item} />
))}

// ✅ Lazy load heavy components
const HeavyComponent = React.lazy(() => import('./HeavyComponent'));

// ✅ Debounce expensive operations
const debouncedSave = debounce(saveToBackend, 500);
```

**DON'T**:
```typescript
// ❌ Create new objects/arrays in render
<Component data={{ value: 1 }} />  // New object every render

// ❌ Inline arrow functions as props (unless memoized)
<Button onClick={() => handleClick(id)} />  // New function every render

// ❌ Large initial bundles
import * as hugeLibrary from 'huge-library';  // Import only what you need
```

### Zustand Performance

```typescript
// ✅ Subscribe to specific state
const characterName = useGameStore(state => state.gameState.character.name);

// ❌ Subscribe to entire store
const store = useGameStore();  // Re-renders on ANY state change
```

## Security Best Practices

### Frontend Security

**DO**:
- ✅ Validate all user input
- ✅ Sanitize data before displaying
- ✅ Use HTTPS in production
- ✅ Store tokens securely (httpOnly cookies are better than localStorage)
- ✅ Implement CSRF protection
- ✅ Set proper CORS headers

**DON'T**:
- ❌ Trust user input
- ❌ Store sensitive data in localStorage
- ❌ Expose API keys in frontend code
- ❌ Use innerHTML with user content

### Backend Security

**DO**:
- ✅ Use parameterized queries (prevent SQL injection)
- ✅ Hash passwords with bcrypt
- ✅ Validate and sanitize all input
- ✅ Use JWT with expiration
- ✅ Rate limit API endpoints
- ✅ Use environment variables for secrets

**DON'T**:
- ❌ Log sensitive data (passwords, tokens)
- ❌ Return detailed error messages to client
- ❌ Trust client-side validation alone

// ❌ Missing alt text

// ❌ Color as only indicator
<span style={{ color: 'red' }}>Error</span>  // Add icon or text too

## Code Review Checklist

Before submitting code for review:

**Functionality**:
- [ ] Code works as intended
- [ ] Edge cases are handled
- [ ] Error cases are handled

**Code Quality**:
- [ ] Follows project conventions
- [ ] No unused variables or imports
- [ ] No commented-out code
- [ ] No console.logs (unless intentional logging)
- [ ] No TODO comments without explanation

**TypeScript**:
- [ ] All types are explicit
- [ ] No `any` types
- [ ] Compiles without errors or warnings

**Testing**:
- [ ] Manual testing completed
- [ ] Existing tests still pass
- [ ] New features have tests (if applicable)

**Documentation**:
- [ ] Code is self-documenting
- [ ] Complex logic has comments
- [ ] Public APIs have JSDoc

**Performance**:
- [ ] No obvious performance issues
- [ ] Components are memoized where appropriate
- [ ] No unnecessary re-renders

**Security**:
- [ ] No security vulnerabilities
- [ ] User input is validated
- [ ] Sensitive data is not exposed

## Conclusion

These standards ensure the Axiomancer codebase remains clean, maintainable, and scalable. When in doubt:

1. **Keep it simple**
2. **Make it explicit**
3. **Remove unused code**
4. **Follow conventions**
5. **Think about the next developer** (which might be future you!)

Remember: "Keep it slow!" - quality over quantity.
