## Architecture Pattern: Layered Architecture

### Request Flow
```
HTTP Request
    ↓
Route Handler (routes/*.ts)
    ↓
Middleware (auth.middleware.ts)
    ↓
Controller (controllers/*.ts) [optional layer]
    ↓
Service Layer (services/*.ts)
    ↓
Database (SQLite / PostgreSQL)
    ↓
Response back through layers
```

## Core Components

### 1. Entry Point (`src/index.ts`)

**Purpose**: Bootstrap the Express application

**Key Responsibilities**:
- Load environment variables via dotenv
- Configure CORS for cross-origin requests
- Register middleware (JSON parsing, URL encoding)
- Mount route handlers
- Initialize database connection
- Start HTTP server
- Implement health check endpoint

**Critical Code**:
```typescript
// Database must be initialized before server starts
await DatabaseService.initialize();

// Health check for container orchestration
app.get('/health', (req, res) => {
  res.status(200).json({ status: 'OK', timestamp: new Date().toISOString() });
});
```

### 2. Database Service (`src/services/database.service.ts`)

**Purpose**: Abstraction layer for database operations supporting both SQLite and PostgreSQL

**Key Features**:
- **Dual Database Support**: Automatically detects and uses PostgreSQL or falls back to SQLite
- **Schema Management**: Auto-creates tables if they don't exist
- **Type Safety**: Returns typed objects, not raw rows

**Tables**:

#### `users` table
```sql
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  first_name VARCHAR(255) NOT NULL,
  last_name VARCHAR(255) NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

#### `character_states` table
```sql
CREATE TABLE character_states (
  id SERIAL PRIMARY KEY,
  user_id INTEGER NOT NULL,
  character_data TEXT NOT NULL,      -- JSON serialized Character object
  current_location TEXT NOT NULL,
  current_node TEXT NOT NULL,
  story_data TEXT NOT NULL,          -- JSON serialized story flags
  inventory_data TEXT NOT NULL,      -- JSON serialized inventory
  locations_data TEXT NOT NULL,      -- JSON serialized locations/nodes
  quest_log_data TEXT NOT NULL,      -- JSON serialized quest log
  map_energy INTEGER DEFAULT 100,
  max_map_energy INTEGER DEFAULT 100,
  game_phase TEXT DEFAULT 'exploration',
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (user_id) REFERENCES users (id) ON DELETE CASCADE
);
```

**Key Methods**:
- `initialize()`: Connect to DB and create tables
- `createUser()`: Insert new user with hashed password
- `getUserByEmail()`: Retrieve user for login
- `saveCharacterState()`: Upsert character game state
- `getCharacterState()`: Retrieve and deserialize character state
- `deleteCharacterState()`: Remove character data

**JSON Serialization Pattern**:
```typescript
// Saving
character_data: JSON.stringify(state.character)

// Loading
character: JSON.parse(row.character_data)
```

**Database Detection Logic**:
```typescript
if (process.env.DB_HOST && process.env.DB_NAME) {
  // Use PostgreSQL
} else {
  // Use SQLite
}
```

### 3. Authentication Service (`src/services/auth.service.ts`)

**Purpose**: Handle user authentication logic

**Key Responsibilities**:
- Password hashing via bcryptjs
- User registration
- User login validation
- JWT token generation

**Methods**:
- `register()`: Create new user account
- `login()`: Validate credentials and return JWT
- `hashPassword()`: bcrypt hashing
- `comparePasswords()`: bcrypt comparison
- `generateToken()`: Sign JWT with userId and email

**Security Practices**:
- Never return password_hash to frontend
- Use bcrypt with default salt rounds (10)
- JWT includes userId and email only
- JWT secret from environment variable

### 4. Authentication Middleware (`src/middleware/auth.middleware.ts`)

**Purpose**: Protect routes requiring authentication

**Function**: `authenticateToken(req, res, next)`

**Process**:
```
1. Extract token from Authorization header
2. Verify JWT signature with JWT_SECRET
3. Decode payload (userId, email)
4. Attach payload to req.user
5. Call next() or return 401/403
```

**Usage**:
```typescript
router.post('/save', authenticateToken, async (req, res) => {
  const userId = req.user?.userId; // Available after middleware
  // ...
});
```

**Authorization Header Format**:
```
Authorization: Bearer <jwt-token>
```

### 5. Error Middleware (`src/middleware/error.middleware.ts`)

**Purpose**: Centralized error handling

**Function**: `errorHandler(err, req, res, next)`

**Behavior**:
- Logs error stack in development
- Returns consistent error format
- Includes stack trace only in development mode

**Response Format**:
```typescript
{
  message: string,
  statusCode: number,
  stack?: string  // Only in development
}
```

**NOTE**: There is a type mismatch here! Frontend expects `error` not `message`. See `shared-types.md` for details.

### 6. Routes

#### Authentication Routes (`src/routes/auth.routes.ts`)

**Endpoints**:
- `POST /api/auth/register` - Create new user account
- `POST /api/auth/login` - Authenticate and receive JWT

**Request/Response Types**:
```typescript
// Register
Request: { email, password, firstName, lastName }
Response: { user: User, token: string }

// Login
Request: { email, password }
Response: { user: User, token: string }
```

#### Character Routes (`src/routes/character.routes.ts`)

**All routes require authentication** via `authenticateToken` middleware

**Endpoints**:
- `POST /api/character/save` - Save game state
- `GET /api/character/load` - Load game state
- `GET /api/character/exists` - Check if character exists
- `DELETE /api/character/delete` - Delete character

**Request/Response Types**:
```typescript
// Save
Request: SavedCharacterData (entire game state)
Response: { message: "Character saved successfully" }

// Load
Response: SavedCharacterData

// Exists
Response: { exists: boolean }

// Delete
Response: { message: "Character deleted successfully" }
```

**Character Save Payload Structure**:
```typescript
{
  character: Character,        // Full character object
  currentLocation: string,
  currentNode: string,
  story: StoryState,
  inventory: InventoryState,
  locations: Record<string, GameLocation>,
  questLog: Quest[],
  mapEnergy: number,
  maxMapEnergy: number,
  gamePhase: string,
  savedAt: number
}
```

## Environment Variables

**Required**:
- `NODE_ENV`: 'development' | 'production'
- `PORT`: Server port (default: 3001)
- `JWT_SECRET`: Secret key for signing JWTs

**Optional (PostgreSQL)**:
- `DB_HOST`: Database host (triggers PostgreSQL mode)
- `DB_PORT`: Database port (default: 5432)
- `DB_NAME`: Database name
- `DB_USER`: Database user
- `DB_PASSWORD`: Database password

**If PostgreSQL vars are missing**: Falls back to SQLite (`./database.sqlite`)

## Common Development Tasks

### Add a New API Endpoint

1. **Define Types** in `src/types/index.ts`
2. **Create Service Method** in appropriate service file
3. **Create Route Handler** in appropriate route file
4. **Add Middleware** if needed (auth, validation)
5. **Mount Route** in `src/index.ts`
6. **Update Frontend Types** to match
7. **Test with REST Client** or Postman

Example:
```typescript
// 1. Type
export interface SkillData {
  name: string;
  description: string;
}

// 2. Service (in database.service.ts)
static async saveSkill(userId: number, skill: SkillData): Promise<void> {
  // Implementation
}

// 3. Route
router.post('/skill', authenticateToken, async (req, res) => {
  const userId = req.user?.userId;
  await DatabaseService.saveSkill(userId, req.body);
  res.status(200).json({ message: 'Skill saved' });
});
```

### Add Database Table

1. **Add CREATE TABLE statement** to `DatabaseService.initialize()`
2. **Add migration logic** if needed for existing databases
3. **Add CRUD methods** in DatabaseService
4. **Test locally with SQLite** first
5. **Verify in PostgreSQL** via Docker

### Update JWT Payload

1. **Modify JwtPayload interface** in `src/types/index.ts`
2. **Update token generation** in `auth.service.ts`
3. **Update middleware** in `auth.middleware.ts`
4. **Consider token versioning** to handle existing tokens

## Security Best Practices

### 1. Password Handling
- ✅ Always hash passwords with bcrypt
- ✅ Never log passwords
- ✅ Never return password_hash to frontend
- ✅ Use strong JWT secrets in production

### 2. SQL Injection Prevention
- ✅ Use parameterized queries (already implemented)
- ❌ Never concatenate user input into SQL strings

### 3. JWT Security
- ✅ Use strong, random JWT_SECRET
- ✅ Short expiration times (consider adding exp claim)
- ⚠️ Currently no token expiration implemented
- ⚠️ No refresh token mechanism

### 4. CORS Configuration
- ✅ CORS enabled for cross-origin requests
- ⚠️ Currently allows all origins (consider restricting in production)

### 5. Error Handling
- ✅ Centralized error middleware
- ✅ No sensitive data in error messages
- ✅ Stack traces only in development

## Performance Considerations

### Database Connection Pooling
- PostgreSQL uses connection pooling by default (pg library)
- SQLite is single-connection (sufficient for local dev)

### JSON Serialization
- Character state is stored as JSON TEXT
- Parsing happens on every load (acceptable for current scale)
- Consider caching for high-traffic scenarios

### Auto-Save Frequency
- Frontend debounces saves to 500ms
- Consider rate limiting if abuse is detected

## Error Handling Patterns

### Service Layer
```typescript
// Throw errors, let middleware handle them
if (!user) {
  throw new Error('User not found');
}
```

### Route Handlers
```typescript
// Use try-catch and explicit status codes
try {
  const result = await AuthService.login(email, password);
  res.status(200).json(result);
} catch (error) {
  res.status(401).json({ error: 'Invalid credentials' });
}
```

### Middleware
```typescript
// Pass errors to error handler
if (!token) {
  return res.status(401).json({ error: 'No token provided' });
}
```

## Known Issues and TODOs

1. **ApiError Type Mismatch**: Frontend expects `error`, backend sends `message`
2. **No JWT Expiration**: Tokens never expire
3. **No Refresh Token**: Users must re-login when token expires (once implemented)
4. **Password Validation**: No complexity requirements enforced
5. **Rate Limiting**: No protection against brute force attacks
6. **CORS**: Allows all origins (should be restricted in production)
7. **Database Migrations**: No formal migration system
8. **Logging**: Console.log only, no structured logging
9. **Monitoring**: No application monitoring or error tracking

## Code Style Guidelines

### File Naming
- Use kebab-case: `auth.service.ts`, `database.service.ts`
- Suffix by type: `.controller.ts`, `.service.ts`, `.routes.ts`, `.middleware.ts`

### Exports
- Named exports only (no default exports)
- Export interfaces from types/index.ts

### Async/Await
- Prefer async/await over .then() chains
- Always handle errors with try-catch

### Type Annotations
- Explicit return types on all functions
- No `any` types (use `unknown` if necessary)
- Interface over type for objects

### Comments
- JSDoc comments for exported functions
- Inline comments for complex logic
- Avoid obvious comments

Example:
```typescript
/**
 * Authenticates a user and returns a JWT token
 * @param email - User's email address
 * @param password - User's password (plaintext)
 * @returns AuthResponse with user object and token
 * @throws Error if credentials are invalid
 */
export async function login(email: string, password: string): Promise<AuthResponse> {
  // Implementation
}
```
