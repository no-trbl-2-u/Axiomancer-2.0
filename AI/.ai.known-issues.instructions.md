## Critical Known Issues

### 1. Character Persistence Problems

**Status**: 🔴 HIGH PRIORITY

**Symptoms**:
- User creates character but after page refresh, sees character creation screen again
- Character data appears to be "lost" between sessions
- User forced to create new character repeatedly

**Root Causes** (see `CHARACTER_PERSISTENCE_ANALYSIS.md` for full details):

1. **No Automatic Load on App Startup**:
   - gameStore does NOT have Zustand persist middleware
   - Character data is NOT automatically loaded from backend on app start
   - User must manually navigate to character-selection page and click "Continue Journey"

2. **Game Page Shows Creation Screen by Default**:
   - If gameStore is empty (which it always is on fresh page load), GamePage shows CharacterCreationScreen
   - This happens even if user has saved character in database

3. **Character Route Flow Issue**:
   - User logs in → redirected to `/`
   - CharacterRoute checks backend for existing character
   - If exists → redirects to `/character-selection`
   - User must click "Continue Journey"
   - Only THEN does character load into gameStore
   - If user navigates directly to `/game`, character won't be loaded

**Recommended Fixes**:

**Priority 1**: Add Zustand persist to gameStore
```typescript
// In gameStore.ts
import { persist } from 'zustand/middleware';

export const useGameStore = create<GameStore>()(
  devtools(
    persist(
      (set, get) => ({ /* store implementation */ }),
      {
        name: 'axiomancer-game-store',
        partialize: (state) => ({
          gameState: state.gameState,
        }),
      }
    ),
    {
      name: 'axiomancer-game-store-devtools',
    }
  )
);
```

**Priority 2**: Auto-load character on GamePage mount
```typescript
// In GamePage.tsx
useEffect(() => {
  const loadIfNeeded = async () => {
    if (!character.name) {
      const success = await useGameStore.getState().loadSavedCharacter();
      if (!success) {
        // No saved character, show creation screen
        navigate('/character-creation');
      }
    }
  };
  loadIfNeeded();
}, []);
```

**Priority 3**: Add visual save/load feedback
```typescript
const [saveStatus, setSaveStatus] = useState<'idle' | 'saving' | 'saved' | 'error'>('idle');

// Show indicator in UI
{saveStatus === 'saving' && <Spinner />}
{saveStatus === 'saved' && <CheckIcon />}
{saveStatus === 'error' && <ErrorIcon />}
```

### 2. Type Mismatches Between Frontend and Backend

**Status**: 🟡 MEDIUM PRIORITY

**Issue**: ApiError type differs between frontend and backend

**Backend** (`axiomancer-backend/src/types/index.ts`):
```typescript
interface ApiError {
  message: string;
  statusCode: number;
  stack?: string;
}
```

**Frontend** (`axiomancer-frontend/src/types/index.ts`):
```typescript
interface ApiError {
  error: string;        // ⚠️ Should be "message"
  stack?: string;
}
```

**Impact**:
- Frontend expects `error.error` but receives `error.message`
- Error handling code may fail silently
- User sees generic error messages instead of specific ones

**Fix**:
```typescript
// Option 1: Update frontend to match backend (RECOMMENDED)
export interface ApiError {
  message: string;
  statusCode: number;
  stack?: string;
}

// Option 2: Update backend to match frontend
export interface ApiError {
  error: string;
  statusCode: number;
  stack?: string;
}
```

**Files to Update**:
- `axiomancer-frontend/src/types/index.ts`
- Any frontend code that accesses `error.error` → change to `error.message`
- Check `authService.ts`, `characterService.ts`, login/register pages

See `shared-types.md` for complete analysis.

### 4. Character ID Generation Collision Risk

**Status**: 🟢 LOW PRIORITY

**Issue**: Character IDs use `Date.now().toString()`

```typescript
// In gameStore.ts
id: Date.now().toString()
```

**Problem**:
- If two characters created in same millisecond → same ID
- Unlikely but possible, especially in automated tests

**Fix**:
```typescript
// Use crypto.randomUUID() or nanoid
import { nanoid } from 'nanoid';

id: nanoid()  // or crypto.randomUUID() if available
```

### 5. Auto-Save Debouncing Can Lose Data

**Status**: 🟡 MEDIUM PRIORITY

**Issue**: Game saves are debounced by 500ms

```typescript
setTimeout(() => {
  get().saveGame();
}, 500);
```

**Problem**:
- If user closes browser/tab within 500ms of last action, save doesn't complete
- Network interruption during save = data lost
- No retry mechanism

**Symptoms**:
- "I made progress but it wasn't saved"
- Especially common on mobile (browser killed in background)

**Recommended Fixes**:

1. **Add beforeunload handler**:
```typescript
useEffect(() => {
  const handleBeforeUnload = (e: BeforeUnloadEvent) => {
    if (hasPendingSave) {
      e.preventDefault();
      e.returnValue = '';  // Show browser warning
      saveGameSync();  // Attempt synchronous save
    }
  };
  window.addEventListener('beforeunload', handleBeforeUnload);
  return () => window.removeEventListener('beforeunload', handleBeforeUnload);
}, []);
```

2. **Add save retry logic**:
```typescript
const saveGameWithRetry = async (maxRetries = 3) => {
  for (let i = 0; i < maxRetries; i++) {
    try {
      await saveCharacter(gameState);
      return true;
    } catch (error) {
      console.error(`Save attempt ${i + 1} failed:`, error);
      if (i === maxRetries - 1) throw error;
      await new Promise(resolve => setTimeout(resolve, 1000 * (i + 1)));
    }
  }
};
```

3. **Add localStorage backup**:
```typescript
// Save to localStorage as backup
localStorage.setItem('game-backup', JSON.stringify(gameState));

// On load, check if backend load fails
if (backendCharacter) {
  loadFromBackend();
} else {
  const backup = localStorage.getItem('game-backup');
  if (backup) {
    showPrompt('Load from backup?');
  }
}
```

### 6. Auth Token Retrieval is Fragile

**Status**: 🟡 MEDIUM PRIORITY

**Issue**: characterService manually parses localStorage for auth token

```typescript
// In characterService.ts
const getAuthToken = (): string | null => {
  const storeData = localStorage.getItem('axiomancer-auth-store');
  if (storeData) {
    const parsed = JSON.parse(storeData);
    return parsed.state?.token || null;
  }
  return null;
};
```

**Problem**:
- If authStore structure changes, this breaks
- Tight coupling between services
- No error handling for JSON.parse

**Fix**:
```typescript
// Create shared auth utility
// In utils/auth.ts
export const getAuthToken = (): string | null => {
  try {
    const storeData = localStorage.getItem('axiomancer-auth-store');
    if (!storeData) return null;
    
    const parsed = JSON.parse(storeData);
    return parsed?.state?.token || null;
  } catch (error) {
    console.error('Failed to parse auth token:', error);
    return null;
  }
};

// Use in both authService and characterService
import { getAuthToken } from '../utils/auth';
```

### 7. No JWT Expiration

**Status**: 🟡 MEDIUM PRIORITY (Security Issue)

**Issue**: JWT tokens never expire

**Backend** (`auth.service.ts`):
```typescript
const token = jwt.sign(
  { userId: user.id, email: user.email },
  process.env.JWT_SECRET || 'secret'
  // No expiresIn option!
);
```

**Impact**:
- Stolen token is valid forever
- Security risk
- No way to force re-authentication

**Fix**:
```typescript
// Add expiration
const token = jwt.sign(
  { userId: user.id, email: user.email },
  process.env.JWT_SECRET || 'secret',
  { expiresIn: '7d' }  // 7 days, adjust as needed
);

// Add refresh token mechanism
const refreshToken = jwt.sign(
  { userId: user.id },
  process.env.REFRESH_SECRET || 'refresh-secret',
  { expiresIn: '30d' }
);

// Return both tokens
return { user, token, refreshToken };
```

**Frontend**:
- Store both tokens
- When access token expires, use refresh token to get new access token
- If refresh token expires, require login

### 8. No Save Confirmation Feedback

**Status**: 🟢 LOW PRIORITY (UX Issue)

**Issue**: Users don't know if their game saved successfully

**Current**:
- Only console.log messages
- No UI indication

**Fix**:
```typescript
// Add to gameStore
const [saveStatus, setSaveStatus] = useState<SaveStatus>('idle');

// In saveGame action
saveGame: async () => {
  setSaveStatus('saving');
  try {
    await saveCharacter(gameState);
    setSaveStatus('saved');
    setTimeout(() => setSaveStatus('idle'), 2000);
  } catch (error) {
    setSaveStatus('error');
    showErrorNotification('Failed to save game');
  }
}

// In UI (corner of screen)
<SaveIndicator status={saveStatus} />
```

## Testing Checklist Before Major Changes

Before making significant changes:

1. **Backup database**:
   ```bash
   cp axiomancer-backend/database.sqlite axiomancer-backend/database.backup.sqlite
   ```

2. **Test current functionality**:
   - Can create user?
   - Can login?
   - Can create character?
   - Can save character?
   - Can load character?
   - Can navigate map?
   - Can enter combat?

3. **Document current issues**: List what's broken NOW

4. **Make changes incrementally**: Don't change everything at once

5. **Test after each change**: Verify nothing else broke

6. **Commit frequently**: Small, atomic commits
