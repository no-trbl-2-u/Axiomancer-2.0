## Architecture Pattern: Flux-like with Zustand

### Data Flow
```
User Interaction
    ↓
Component Event Handler
    ↓
Zustand Store Action
    ↓
State Update + Side Effects (API calls, auto-save)
    ↓
Component Re-renders (subscribed to store)
```

### Store-Component Relationship
- **Stores are the source of truth** for all application state
- **Components are thin** - they display data and dispatch actions
- **Business logic lives in stores**, not components
- **Services handle API communication**, called by stores

### 3. Zustand Stores

#### Auth Store (`src/stores/authStore.ts`)

**Purpose**: Manage authentication state

**State**:
```typescript
{
  user: User | null,
  token: string | null,
  isAuthenticated: boolean,
  isLoading: boolean
}
```

**Actions**:
- `login(credentials)`: Authenticate user
- `register(data)`: Create new account
- `logout()`: Clear auth state
- `initAuth()`: Restore auth from localStorage (automatic via persist middleware)

**Persistence**:
```typescript
persist(
  (set, get) => ({ /* state */ }),
  {
    name: 'axiomancer-auth-store',  // localStorage key
    partialize: (state) => ({
      user: state.user,
      token: state.token,
      isAuthenticated: state.isAuthenticated,
    }),
  }
)
```

#### Game Store (`src/stores/gameStore.ts`)

**Purpose**: All game mechanics and state (UI-agnostic)

**This is the heart of the application** - 1600+ lines of game logic

**State Structure**:
```typescript
{
  gameState: {
    character: Character,
    currentLocation: string,
    currentNode: string,
    story: StoryState,
    inventory: InventoryState,
    locations: Record<string, GameLocation>,
    questLog: Quest[],
    mapEnergy: number,
    maxMapEnergy: number,
    combat: CombatState | null,
    gamePhase: 'exploration' | 'combat' | 'dialogue' | 'event'
  },
  currentScreen: GameScreen
}
```

**Key Action Categories**:

1. **Character Management**:
   - `createCharacter(data)`: Initialize new character
   - `loadSavedCharacter()`: Load from backend
   - `updateCharacter(updates)`: Modify character properties
   - `assignStatPoint(stat)` / `unassignStatPoint(stat)`: Stat allocation
   - `gainExperience(amount)`: Level progression

2. **Location & Navigation**:
   - `moveToLocation(locationId)`: Change map
   - `moveToNode(nodeId)`: Move to node on current map
   - `unlockNode(locationId, nodeId)`: Make node accessible

3. **Combat System**:
   - `startCombat(enemyId)`: Initialize combat encounter
   - `endCombat()`: Clean up after combat
   - `updateCombat(updates)`: Modify combat state during battle

4. **Inventory & Equipment**:
   - `updateInventory(updates)`: Modify inventory
   - `equipItem(slot, item)`: Equip item to slot
   - `unequipItem(slot)`: Remove equipped item

5. **Skill System**:
   - `learnSkill(skill)`: Add skill to character
   - `canLearnSkill(skill)`: Check prerequisites
   - `equipSkill(skill, aspect)`: Assign skill to philosophical aspect
   - `unequipSkill(skillId, aspect)`: Remove skill from slot

6. **Quest System**:
   - `completeQuest(questId)`: Mark quest as complete
   - `addQuest(quest)`: Add new quest to log

7. **Save System**:
   - `saveGame()`: Persist state to backend

**Auto-Save Mechanism**:
Most mutations trigger a debounced save:
```typescript
setTimeout(() => {
  get().saveGame();
}, 500);
```

**Save Conditions**:
```typescript
saveGame: async () => {
  const state = get();
  const char = state.gameState.character;
  
  // Only save if character is valid
  if (char && char.name && char.id !== 'placeholder') {
    await saveCharacter(state.gameState);
  }
}
```

**NOTE**: gameStore does NOT use persist middleware, relying entirely on backend saves

### 4. Services Layer

#### Auth Service (`src/services/authService.ts`)

**Purpose**: HTTP client for authentication endpoints

**Methods**:
- `login(credentials)`: POST `/api/auth/login`
- `register(data)`: POST `/api/auth/register`

**Token Storage**: Handled by authStore persist middleware

#### Character Service (`src/services/characterService.ts`)

**Purpose**: HTTP client for character persistence

**Methods**:
- `saveCharacter(gameState)`: POST `/api/character/save`
- `loadCharacter()`: GET `/api/character/load`
- `hasExistingCharacter()`: GET `/api/character/exists`
- `deleteCharacter()`: DELETE `/api/character/delete`

**Auth Token Retrieval** (Important):
```typescript
const getAuthToken = (): string | null => {
  const storeData = localStorage.getItem('axiomancer-auth-store');
  if (storeData) {
    const parsed = JSON.parse(storeData);
    return parsed.state?.token || null;
  }
  return null;
};
```

**Why Manual Parsing?**:
- characterService cannot import from authStore (circular dependency)
- Directly reads localStorage where Zustand persist stores the token

**Headers**:
```typescript
headers: {
  'Content-Type': 'application/json',
  'Authorization': `Bearer ${token}`
}
```

```typescript
  // Convert old stat system to new
  if (data.character.oldStatName) {
    data.character.newStatName = data.character.oldStatName;
    delete data.character.oldStatName;
```

## Component Design Patterns

### 1. Zustand Store Consumption

**Basic Hook Usage**:


**Using Actions from Store**:

## State Management Best Practices

### 1. Store Organization

**DO**:
- ✅ Keep stores focused (auth, game, ui)
- ✅ Put business logic in stores, not components
- ✅ Use actions for all state mutations
- ✅ Compute derived data in selectors

**DON'T**:
- ❌ Put UI-specific state in stores (use local state)
- ❌ Mutate state directly (use set() function)
- ❌ Create circular dependencies between stores

### 2. Component-Store Interaction

**DO**:
- ✅ Subscribe to minimal needed state
- ✅ Use shallow comparison for objects
- ✅ Extract action functions outside render

**DON'T**:
- ❌ Subscribe to entire store if not needed
- ❌ Create new function references in selectors
- ❌ Call store actions during render

### 3. Data Persistence

**DO**:
- ✅ Use Zustand persist for auth state
- ✅ Use backend saves for game state
- ✅ Debounce save operations
- ✅ Handle save failures gracefully

**DON'T**:
- ❌ Store sensitive data in localStorage
- ❌ Assume saves always succeed
- ❌ Save on every state change

## Performance Optimization

### 1. React.memo
```typescript
export const ExpensiveComponent = React.memo(({ data }) => {
  // Component that should only re-render when props change
}, (prevProps, nextProps) => {
  // Custom comparison function
  return prevProps.data.id === nextProps.data.id;
});
```

### 2. Zustand Selectors
```typescript
// BAD - Re-renders on any gameState change
const gameState = useGameStore(state => state.gameState);

// GOOD - Only re-renders when character changes
const character = useGameStore(state => state.gameState.character);
```

### 3. Lazy Loading
```typescript

```

### 4. Image Optimization
- Use appropriate image formats (WebP for photos, PNG for graphics)
- Compress images before committing
- Use `loading="lazy"` for images below the fold

## Known Issues and Gotchas

1. **Character Not Loading**: gameStore has no persist middleware - see `CHARACTER_PERSISTENCE_ANALYSIS.md`
2. **Type Mismatches**: Frontend/backend types differ - see `shared-types.md`
3. **Two Combat Systems**: Both combatState.ts and newCombat.ts exist - see `Types-Issue.md`
4. **Manual Token Retrieval**: characterService manually parses localStorage
5. **Auto-Save Debouncing**: 500ms delay means rapid actions might not save
6. **Character ID Collisions**: Uses Date.now() which could cause issues

## Code Style Guidelines

### File Naming
- Components: PascalCase (e.g., `CharacterScreen.tsx`)
- Utilities: camelCase (e.g., `characterSave.ts`)
- Stores: camelCase (e.g., `gameStore.ts`)
- Types: camelCase (e.g., `game.ts`)

### Imports
- React import first
- External libraries
- Internal imports (stores, components, utils, types)
- Styles last

Example:
```typescript
import React from 'react';
import styled from '@emotion/styled';
import { useNavigate } from 'react-router-dom';

import { useGameStore } from '../stores/gameStore';
import { Button } from '../components/shared/Button';
import { calculateMaxHP } from '../utils/statCalculations';
import { Character } from '../types/game';

// Component code
```

### Component Exports
- Named exports preferred
- Export component and related types together

### TypeScript
- Explicit types for props, state, return values
- No `any` types
- Use interfaces for object shapes
- Use types for unions and primitives
